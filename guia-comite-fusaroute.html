01

Arquitectura del Proyecto

🏛️ Rigor de Ingeniería · Nivel Comité Evaluador

FusaRoute implementa una Arquitectura Hexagonal (Puertos y Adaptadores) con inversión de dependencias estricta. La regla canónica inquebrantable es: la dependencia siempre apunta hacia adentro.

Capa Externa: INFRASTRUCTURE Spring Boot & Adaptadores

adapter/in/web (@RestController, DTOs, GlobalExceptionHandler) • adapter/out/persistence (JPA, Supabase) • adapter/out/security (BCrypt, Nimbus JWT) • config (SecurityConfig, UseCaseConfig)

↓ ↓ ↓   DEPENDE DE   ↓ ↓ ↓
Capa Intermedia: APPLICATION Casos de Uso (POJOs)

RegisterUserService, LoginService, ListActiveRoutesService, GetRouteDetailService.
Cero anotaciones de Spring: reciben sus puertos por constructor para permitir pruebas unitarias con Mockito en milisegundos sin arrancar el contexto.

↓ ↓ ↓   DEPENDE DE   ↓ ↓ ↓
Capa Central: DOMAIN (El Núcleo Intocable) Cero Frameworks

Java 25 Puro: Modelos (Route, User, Fare, Email, PasswordPolicy), Puertos In/Out y Excepciones de negocio. Terminantemente prohibido importar Spring, JPA, Jackson o HTTP.

Vigilancia Automatizada con ArchUnit: La pureza arquitectónica no se vigila a mano en los Pull Requests; se evalúa en tiempo de compilación con HexagonalArchitectureTest.java. Si un desarrollador agrega un @Entity o @Autowired en el dominio, Maven aborta el build automáticamente.

🧒 Mini Teen-Explanation · Modo Pelao / Flash Mental

"El Dominio es como el motor de un Ferrari. El motor solo sabe acelerar y quemar gasolina; le importa un carajo si el carro tiene llantas de repuesto, si la carrocería es azul o si el chofer habla inglés o chino. Los Puertos son los huecos universales para los tornillos y las mangueras. La Infraestructura (Spring Boot, Supabase, Google Maps) son los repuestos intercambiables que le conectamos afuera. Si la base de datos se incendia mañana y cambiamos a otra, el motor sigue andando idéntico porque no depende de nadie."

🛡️ Respuesta de Choque ante el Comité
Pregunta del Profe Luiferney: "¿Por qué no anotaron los Use Cases directamente con @Service en vez de crear UseCaseConfig?"
Respuesta contundente: "Para respetar el principio de desacoplamiento de la Arquitectura Hexagonal. Al no acoplar la capa application al framework de Spring con anotaciones propietarias, nuestros casos de uso son POJOs puros testeables en milisegundos sin levantar el contenedor de inversión de control de Spring, y el cableado de dependencias se aísla de forma explícita en la infraestructura a través de UseCaseConfig."

Estructura del Proyecto

🏛️ Rigor de Ingeniería · Organización Paquete a Paquete

El código fuente se estructura en paquetes semánticos que reflejan los límites del hexágono:

Paquete / Ruta Rol Arquitectónico Responsabilidad Concreta
com.fusaroute.domain.model Entidades & VOs Modelos inmutables (Java records) y Value Objects autocontenidos: Route, Fare, User, Email, PasswordPolicy.
com.fusaroute.domain.port.in Inbound Ports Interfaces de lo que el exterior puede solicitar: RegisterUserUseCase, LoginUseCase, ListActiveRoutesUseCase, GetRouteDetailUseCase.
com.fusaroute.domain.port.out Outbound Ports Interfaces de lo que el dominio necesita: UserRepositoryPort, RouteRepositoryPort, PasswordHasherPort, TokenIssuerPort.
com.fusaroute.application.usecase Application Services Orquestación de casos de uso (*Service.java). Aplican reglas, llaman puertos de salida y coordinan el flujo sin tocar SQL ni HTTP.
infrastructure.adapter.in.web Adaptador Web (REST) @RestController, DTOs de petición y respuesta, y el manejador global de excepciones con estándar RFC 9457.
infrastructure.adapter.out.persistence Persistencia Relacional Entidades JPA (RouteJpaEntity, UserJpaEntity), repositorios Spring Data y mappers de traducción a objetos de dominio.
infrastructure.adapter.out.security Mecanismos Criptográficos Implementación concreta de BCrypt con factor de costo 12 y emisor de tokens JWT con Nimbus JOSE.
infrastructure.config IoC & Security Setup Configuración del firewall Spring Security, reglas CORS estrictas, configuración de firma JWT y ensamblaje de Beans.

Dos Modelos Distintos a Propósito: Tenemos Route (dominio) y RouteJpaEntity (persistencia). Duplicar estos campos no es redundancia; es la barrera que permite alterar la estructura de la base de datos o el motor relacional sin quebrar una sola regla de negocio en el frontend o en los casos de uso.

03

Funcionamiento por Separado y Todo Junto

🏛️ Rigor de Ingeniería · Ciclo de Vida y Flujos Integrados

A. Los 3 Flujos Críticos de la API en Acción:

1. Registro de Usuario (POST /api/auth/register - RF-01):

Llega JSON al AuthController → Construye RegisterUserCommand → Invoca RegisterUserService → Valida nombre (máx 120), correo normalizado (trim + lowercase) y contraseña (mín 8 chars, 1 mayús, 1 num, máx 72 bytes) acumulando todos los fallos en una lista → Verifica que el correo no exista en UserRepositoryPort → Hashea con BCrypt (costo 12) → Crea entidad User.register(...) con active=true y rol USER → Persiste en PostgreSQL → Retorna 201 Created con DTO limpio (sin el hash).

2. Inicio de Sesión Blindado (POST /api/auth/login - RF-02 / RNF-05):

Llega JSON al AuthController → Invoca LoginService → Busca el usuario por correo normalizado → Verificación a Tiempo Constante: si el correo existe, compara con BCrypt contra su hash; si el correo NO existe, ejecuta BCrypt contra un hash fantasma (dummyHash) para consumir exactamente la misma cantidad de CPU y no delatar si el correo existe o no → Si es inválido lanza InvalidCredentialsException (401 genérico) → Si es válido emite JWT firmado HS256 válido por 7 días (RNF-04) con claims sub=id y role=USER → Retorna 200 OK.

3. Catálogo y Resolución de Tarifas (GET /api/routes - RF-15):

Llamada pública sin token → RouteController llama a ListActiveRoutesUseCase → Consulta RouteRepositoryPort.findAll() → El adaptador ejecuta consulta optimizada con @BatchSize(50) para evitar el problema de N+1 consultas en barrios y tarifas → Filtra rutas activas → Ejecuta en cada ruta withCurrentFares(today) resolviendo la tarifa vigente hoy (zona horaria Bogotá) y descartando futuras → Ordena con Collator de Colombia ("es-CO") → Retorna 200 OK.

🧒 Mini Teen-Explanation · Modo Pelao / Flash Mental

"Por separado, cada archivo es un especialista: el validador es el guardia que mira tu cédula, el hasher es el que te pasa por rayos X, y el mapper es el traductor de idiomas. Todo junto es el aeropuerto de FusaRoute: cuando pides login, el guardia y el de los rayos X revisan tu boleto al mismo tiempo exacto para que ningún espía sepa si ya tienes cuenta, y al final te dan una manilla VIP que te deja subir a la buseta por una semana entera."

Significado y Uso de los Archivos Importantes

Archivo Clave Capa Misión Crítica / Para qué sirve
UseCaseConfig.java Infrastructure (Config) Instancia los casos de uso inyectándoles los adaptadores y configura el Clock del sistema fijado a America/Bogota para que los servidores en UTC no desfasen las tarifas.
SecurityConfig.java Infrastructure (Config) Firewall HTTP: Desactiva CSRF (la API es STATELESS con JWT), enumera orígenes CORS permitidos (sin comodín '*'), abre /health, /api/auth/* y el catálogo de rutas, y cierra todo lo demás.
JwtConfig.java Infrastructure (Config) Crea el JwtEncoder y JwtDecoder con algoritmo HS256. Falla el arranque de la app si el JWT_SECRET no tiene al menos 32 bytes (256 bits).
GlobalExceptionHandler.java Infrastructure (Web) Atrapa excepciones y genera respuestas uniformes basadas en el estándar RFC 9457 (ProblemDetail). Evita 500 no controlados.
PasswordPolicy.java Domain (Model) Aplica la política de contraseñas de RF-01. Impone el límite crítico de 72 bytes en UTF-8 derivado de la limitación algorítmica de BCrypt.
Route.java Domain (Model) Record inmutable. Contiene la función pura withCurrentFares(today) que descarta tarifas futuras y resuelve la última vigente por hito.
BCryptPasswordHasher.java Infrastructure (Security) Hasheador seguro con costo 12 (superior al 10 por defecto de Spring). Implementa el dummy hash para neutralizar ataques de enumeración por temporización.
HexagonalArchitectureTest.java Test (Architecture) Test de ArchUnit que analiza los paquetes en el CI. Rompe la compilación si com.fusaroute.domain.. toca Spring o JPA.
pom.xml Root Gestiona dependencias de Java 25, Spring Boot 3.5.16, JaCoCo (bloqueante si la cobertura de domain/application es menor a 70%) y OWASP Dependency Check.

05

Líneas de Código Críticas que Jamás Debes Olvidar

01. Límite de 72 Bytes UTF-8 en PasswordPolicy.java
PasswordPolicy.java (Líneas 46-48) 
if (raw.getBytes(StandardCharsets.UTF_8).length > MAX_BYTES) {
    violations.add(new FieldViolation(FIELD, "La contrasena supera los " + MAX_BYTES + " bytes permitidos"));
}

Por qué es vital: BCrypt procesa únicamente los primeros 72 bytes y descarta silenciosamente el resto. Si dos contraseñas comparten los primeros 72 bytes, tendrían el mismo hash. Medimos en bytes y no en caracteres porque tildes y caracteres especiales ocupan múltiples bytes en UTF-8.

02. Mitigación de Timing Attacks en BCryptPasswordHasher.java
BCryptPasswordHasher.java (Líneas 25 y 33-39) 
private final String dummyHash = encoder.encode("relleno-para-igualar-tiempos");
...
@Override
public boolean matches(String raw, String hashOrNull) {
    if (hashOrNull == null) {
        encoder.matches(raw, dummyHash); // Quema el mismo tiempo de CPU con BCrypt
        return false;
    }
    return encoder.matches(raw, hashOrNull);
}

Por qué es vital: Evita que un atacante descubra qué correos electrónicos están registrados en la plataforma midiendo los milisegundos que tarda la API en responder (ataque de canal lateral por temporización).

03. Resolución de Tarifas Vigentes en Route.java
Route.java (Líneas 40-47) 
Map<String, Fare> latestByPoint = new HashMap<>();
for (Fare fare : fares) {
    if (fare.validFrom().isAfter(today)) continue; // Descarta tarifas futuras
    latestByPoint.merge(fare.referencePoint(), fare,
            (a, b) -> b.validFrom().isAfter(a.validFrom()) ? b : a);
}

Por qué es vital: Se usa HashMap directo y no Collectors.toMap porque en las rutas urbanas el referencePoint es null (tarifa única fija) y los colectores de Java Stream arrojan NullPointerException con claves nulas.

04. Reloj Anclado a Bogotá en UseCaseConfig.java
UseCaseConfig.java (Líneas 35-38) 
@Bean
public Clock clock() {
    return Clock.system(ZoneId.of("America/Bogota"));
}

Por qué es vital: El backend se despliega en Render (servidores en UTC). A las 7:01 PM en Colombia, en UTC ya es el día siguiente. Si usáramos la hora por defecto del contenedor, una tarifa programada para mañana empezaría a regir 5 horas antes de tiempo.

05. ElementCollection con @BatchSize en RouteJpaEntity.java
RouteJpaEntity.java (Líneas 56-60) 
@ElementCollection(fetch = FetchType.LAZY)
@CollectionTable(name = "route_neighborhoods", joinColumns = @JoinColumn(name = "route_id"))
@MapKeyColumn(name = "order_index")
@Column(name = "neighborhood_name", nullable = false, length = 120)
@BatchSize(size = 50)

Por qué es vital: Hibernate prohíbe hacer un JOIN FETCH simultáneo sobre dos listas hijas (generaría MultipleBagFetchException). Usando @BatchSize(size = 50), Hibernate agrupa las consultas en lotes de 50 en un solo WHERE route_id IN (...), evitando el problema del N+1.

🧒 Mini Teen-Explanation · Modo Pelao / Flash Mental

"Estas 5 líneas son tus 'superpoderes': con una evitas que los hackers te engañen con contraseñas gigantes; con otra evitas que sepan si un usuario existe; con otra calculas los precios del bus sin que la app se estrelle; con otra corriges el reloj de los gringos para que no cobren antes de hora en Fusa; y con la última haces que la base de datos descargue 50 rutas de un solo viaje en vez de hacer 50 viajes pendejos por la red."

06

El Porqué de las Decisiones del Proyecto

Decisión Estratégica Alternativa Rechazada Justificación Técnica Contundente
Spring Boot 3.5.16 Spring Boot 4.x La rama 4 es un cambio mayor reciente. En un primer acercamiento a Spring, las librerías satélite, tutoriales y resolución de fallos probados residen en la línea 3.x. Evita perder sprints resolviendo breaking changes del framework.
Java 25 (LTS) Java 17 o 21 Aprovecha la versión de soporte a largo plazo más reciente con Records inmutables nativos, Pattern Matching de alto rendimiento y APIs modernas de colecciones sin bibliotecas de terceros.
Supabase es SOLO PostgreSQL Supabase Auth / Storage Cero Vendor Lock-In. Si usamos el Auth de Supabase nos volvemos dependientes de su infraestructura propietaria. La seguridad y lógica pertenecen a Spring Security + JWT propio en Java.
Rol fusaroute_dev (Sin Superusuario) Usuario postgres Principio de Menor Privilegio: la app jamás se conecta con permisos de administrador general. Si la credencial de DEV se filtra, el impacto se aísla únicamente al esquema fusaroute.
Flyway y ddl-auto=validate Hibernate update o create Hibernate nunca debe alterar el esquema en producción. El DDL es código fuente versionado en scripts SQL auditables en Pull Requests y replicable idéntico en DEV, PRE y PROD.
Sin paradas formales de bus Paradas geográficas fijas En Fusagasugá la buseta se detiene sacando la mano en cualquier tramo (operación tipo taxi). Modelar polígonos geoespaciales requeriría PostGIS (fuera de alcance). Modelamos barrios ordenados y puntos de referencia.
Dominio filtra la mejor ruta Google Maps elige la ruta El catálogo y el cálculo pertenecen a FusaRoute. Google Maps solo se usa como oráculo de tiempo de tránsito sobre rutas ya filtradas. Dejar que Google elija violaría RNF-03 y dejaría el dominio sin cobertura JaCoCo.
Caché de 5 minutos en Google Maps Consultar Maps en cada petición Sostiene el compromiso de rendimiento de p95 < 8.0 segundos y previene el agotamiento prematuro de la cuota gratuita de la API.
🧒 Mini Teen-Explanation · Modo Pelao / Flash Mental

"Cada decisión fue para no pegarnos un tiro en el pie: no usamos tecnologías experimentales que se rompan a mitad de noche; no le damos la llave maestra del edificio al jardinero; no dejamos que Hibernate nos cambie la base de datos a sus espaldas; y no nos inventamos paradas estilo metro de Nueva York porque en Fusa la buseta se agarra sacando la mano en la esquina."

07

Resumen, Explicación y Justificación de la Base de Datos

🏛️ Rigor de Ingeniería · Esquema Relacional y Restricciones DDL

La base de datos corre en PostgreSQL (alojada en Supabase bajo el esquema dedicado fusaroute). El control del esquema lo gestiona Flyway mediante migraciones versionadas inmutables.

Las 4 Tablas del Modelo Actual:

Tabla Columna Destacada Tipo de Dato Justificación Técnica de Ingeniería
users password_hash VARCHAR(72) BCrypt produce siempre 60 caracteres. Configurar 72 deja holgura y bloquea strings desmesurados. La contraseña en texto claro jamás toca la base.
users failed_login_attempts / locked_until SMALLINT / TIMESTAMPTZ Se guardan en la fila del usuario y no en memoria RAM para que el bloqueo temporal de cuenta sobreviva a los reinicios y cold starts de Render.
users active BOOLEAN DEFAULT FALSE Agregada en V4. Nace DEFAULT FALSE para proteger inserciones manuales por SQL; la activación en true la decide el dominio en Java (User.register).
routes path_geojson JSONB (NULLABLE) Postgres valida que sea JSON bien formado. Es NULLABLE porque la búsqueda del catálogo opera por barrios; el GeoJSON solo lo usará el mapa y el modo offline.
route_neighborhoods (route_id, order_index) BIGINT, INT (PK Compuesta) Garantiza el orden estricto de recorrido. La restricción uq_route_neighborhoods_name impide que el mismo barrio se repita dentro de una ruta.
fares amount NUMERIC(10, 2) El dinero nunca se almacena en FLOAT o DOUBLE debido a los errores de redondeo de punto flotante binario (IEEE 754). NUMERIC asegura precisión exacta en pesos.
fares uq_fares_route_point UNIQUE NULLS NOT DISTINCT Característica de PostgreSQL 15+. Hace que dos valores NULL en reference_point (rutas urbanas) choquen entre sí si tienen la misma fecha de vigencia.

Evolución del Esquema en las 4 Migraciones Flyway:

  • V1__crear_usuarios_y_rutas.sql: Estructura inicial con tablas users, routes, route_neighborhoods y fares, más índices de búsqueda por barrio y estado.
  • V2__semilla_rutas_fusagasuga.sql: Semilla con el catálogo oficial de rutas urbanas (Comuneros, Coburgo, Pekín) y veredales decretadas.
  • V3__tarifas_cootransfusa_ruta_pasca.sql: Carga de la tabla oficial de tarifas de Cootransfusa (trayecto Fusagasugá–Pasca con hitos: Sauces $3.000, Alaska $3.550, Pasca $4.300). Demuestra la coexistencia de vigencias 2025 y 2026.
  • V4__usuarios_activos.sql: Evolución que agrega la columna active sin alterar los checksums inmutables de V1 a V3.
🧒 Mini Teen-Explanation · Modo Pelao / Flash Mental

"La base de datos es como una libreta contable que no se borra con corrector. Si el pasaje sube de precio, no tachamos el precio viejo; escribimos un renglón nuevo diciendo 'a partir de hoy rige esto'. Las reglas son tan estrictas que no te deja meter centavos fantasmas, ni registrar dos cuentas con el mismo correo, y si el servidor se duerme, las cuentas bloqueadas siguen bloqueadas."

⚔️ Preguntas Trampa del Comité (Haz click para entrenar)

Click para revelar respuesta
1. "¿Por qué duplicaron clases y crearon Route y RouteJpaEntity? ¿No es código duplicado innecesario?" ↓
Respuesta: "No es código duplicado; es la separación fundamental de la Arquitectura Hexagonal. Route es un modelo inmutable que contiene únicamente reglas de negocio del transporte de Fusagasugá (como el cálculo de tarifas vigentes), mientras que RouteJpaEntity es un modelo de infraestructura atado a las restricciones relacionales de Hibernate y PostgreSQL. Si mañana cambiamos de base de datos o de ORM, el objeto de dominio no sufre una sola alteración."
2. "¿Cómo garantizan que la arquitectura hexagonal no se degrade cuando otro compañero haga commits?" ↓
Respuesta: "Mediante pruebas automatizadas de arquitectura con ArchUnit en el archivo HexagonalArchitectureTest.java. Este test se ejecuta en cada compilación de Maven (mvn test) y en el pipeline de GitHub Actions; si una clase del paquete domain importa Spring, JPA o Jackson, el build falla inmediatamente de manera bloqueante."
3. "¿Por qué no usan las paradas que ofrece la API de Google Maps?" ↓
Respuesta: "Porque en Fusagasugá el sistema de busetas no opera mediante paraderos fijos tipo TransMilenio o metro; se para con la mano en cualquier esquina. Por lo tanto, el catálogo de rutas y barrios es dato propio de FusaRoute. Google Maps únicamente se consulta como un oráculo para cronometrar el tiempo de viaje de rutas ya preseleccionadas por nuestro dominio."
4. "¿Por qué la validación de la contraseña mide 72 bytes en UTF-8 y no caracteres?" ↓
Respuesta: "Porque el algoritmo de cifrado BCrypt trunca y procesa exclusivamente los primeros 72 bytes del texto. En UTF-8, caracteres especiales, tildes o emojis ocupan de 2 a 4 bytes cada uno; si validáramos por caracteres, una contraseña con caracteres especiales podría sobrepasar el límite de 72 bytes y dos contraseñas distintas generarían el mismo hash."
5. "¿Por qué la contraseña hasheada usa factor de coste 12 y qué es ese 'dummyHash'?" ↓
Respuesta: "El factor 12 responde a la métrica RNF-05 (que exige >= 10), garantizando robustez ante hardware moderno sin penalizar la latencia del registro. El dummyHash es una mitigación activa de Timing Attacks: cuando un usuario intenta iniciar sesión con un correo inexistente, ejecutamos BCrypt contra ese hash fantasma para que la CPU tarde exactamente el mismo tiempo en responder, evitando que un atacante descubra qué correos existen en el sistema."
